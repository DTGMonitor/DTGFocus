SensiMap quick guide

  1. Load terrain — drop a .dtm, .dxf, .str, .xyz, .csv or ESRI .asc. Point files get gridded; DXF 3DFACE / polyface meshes and Surpac DTM+STR triangulations are rasterised. No file? Press Load demo open pit.
  2. Place the sensor — type coordinates or use Pick position on model. Antenna height is added to the terrain level when snapping.
  3. Choose the movement vector — steepest / horizontal / vertical / normal, or a custom trend & plunge for a known failure mechanism. A custom vector can also be given as an offset flatter than the steepest line, which keeps each cell's own dip direction.
  4. Compute — sensitivity = |cos θ| between the radar line of sight and the assumed movement vector; 1 = fully measurable, 0 = invisible to the radar.
  5. Plan — add several sensor positions and read the ranking table to find the best site (lowest in the pit usually wins, as long as it is not in the way).

Remember: the sensitivity map is a starting point — it does not know the real failure mechanism.

Parameter reference

Every field also shows this on hover.

1 · Terrain data

Cell sizeRaster resolution in metres. Blank = derived from Target cells. Aim for ≈ ⅓ of your berm width — coarser than that and benches average into a smooth ramp, which biases steepest sensitivity.
Target cellsCells along the longer side when Cell size is blank. 320 fast · 1000 detailed · ceiling ≈ 2.2 M nodes.
Search radiusHow far to hunt for source points when filling a cell. Raise for sparse data.
InterpCombining several points in one cell. IDW weights by 1/d² (default), Nearest preserves original values, Mean is smoothest.
Fill small holes
Fill passes		Fills empty cells from ≥ 4 valid neighbours; each pass grows the fill by one cell. Never modifies cells that already have data.
Smooth normalsOff by default — it averages elevations and erases real bench edges. Only for noisy photogrammetry/laser data.

2 · Radar positions

Easting / Northing / LevelSensor coordinates in your mine grid. Pick position on model sets X/Y by clicking.
Ant. heightMetres added to the terrain when Z = terrain + antenna height is ticked — mast or vehicle height.
Boresight azWhere the antenna faces: degrees from grid north, clockwise (0 = N, 90 = E). Ignored while Auto-aim is on.
Boresight elAntenna tilt. The elevation the boresight points at; positive = aimed up. A sensor on a pit floor watching a high wall is tilted up, and the elevation cone follows it. Leaving this at 0 with a narrow El scan width is the usual reason a whole wall reads out of scan. Auto-aim sets it at the model centre.
Az scan width
El scan width		Total angular coverage, exactly as printed on the datasheet. 90 means ±45° either side of the boresight. Az 360 = no azimuth limit. El width is measured around the tilt above, not around the horizon.
Range min / maxInstrument range gates in metres. Range min is what creates the blind wedge directly under the antenna.
Multi-sensor combinationSelected = one sensor · Best of all = max sensitivity per cell · Average · Which is best = colour by winning sensor.

3 · Sensitivity model

Movement vectorSteepest/Horizontal/Normal are recomputed per cell from the local surface; Vertical/Custom apply one global direction to the whole model. Normal assumes each facet moves straight out of itself (bulging, buckling, rockfall), so its sensitivity map is identical to the amplitude proxy.
Trend az / PlungeCustom vector only: azimuth from north clockwise, plunge below horizontal. Plunge 90 = straight down.
Flatter byCustom vector only, and the alternative to typing a trend: the vector keeps each cell's dip direction and plunges this many degrees less than the local steepest line — the common case of a failure daylighting 10–15° flatter than the face. 0° is identical to Steepest, and an offset that reaches the local slope angle is identical to Horizontal; nothing tips above the horizontal. Being per cell, it is the one custom vector that is not a single global direction.
Occlusion testMarches the sight line over the terrain and flags hidden cells as shadowed. A finer grid finds more shadow — resolved bench crests really do block the beam.
Accuracy / ToleranceSampling step along the ray (in cells), and how far terrain must rise above the ray to count as blocking. Raise the tolerance if noise causes speckled shadows.
Grazing rejectionDrops cells the beam only skims. 90° incidence = line of sight parallel to the surface: fine geometry, no usable return.
ThresholdSensitivity you consider alarm-worthy. Drives usable area, the position ranking and the colour-bar marker.
Displ. factorA hypothetical true movement in mm. The probe and the Measurable displacement layer show sensitivity × this value — what the radar would actually register.

4 · Selection mask

X/Y/Z bounds, slope bandRestrict statistics and position ranking to the slope you care about. Outside cells are dimmed, not deleted. Pick 2 corners draws the box by clicking. Note it masks the analysis, not the gridding.

5 · Layer & colour scale

Sensitivity|cos θ| between line of sight and movement vector. The main product.
Amplitude proxy|cos i| against the surface normal — how well the facet reflects back. Strong amplitude with low sensitivity is still useless.
Visibility1 = the sensor sees it, 0 = shadowed.
Measurable displacementMillimetres of the Displ. factor that survive projection onto the line of sight.
Scale min/maxKeep 0–1 for sensitivity so maps stay comparable between sites and dates.
Bands / GammaBands quantise into classes (0 = continuous). Gamma bends the ramp without moving the ends.
Mask coloursNo-data hole in the survey · Shadowed terrain in the way · Out of scan outside sector/range · Below thr. under the alarm threshold.
